I want to create a Job Application Tracker web application.
Web app has to be accessed by two users with sign-in and log-in options: Jobseekers and Career advisers.
It has to give the possibility to create job application by jobseekers, to add CVs and contact details in the core app.
It has to report a weekly pipeline digest as a scheduled automation.
It has to give the chance of a follow-up nudge if there is no reply from employers as a triggered automation after a job application.
As approval steps, careers advisers have to be able to sign off the jobseekers'CV.

Week03: Jobseekers, Career advisers, Sign-in members, record a CV, show the application outcome.


Requirement: Data model
Minimum: At least 3 related tables, each with a primary key and the foreign keys that link them  
Evidence to submit: Entity relationship diagram (ERD)

Requirement: Automations
Minimum: At least 3: one scheduled, one
triggered by an event, one with a
human approval step
Evidence to submit: Screenshot of each flow plus a
successful test run

Requirements: Role-based access
Minimum: At least 2 roles, enforced on the data itself, not only by hiding buttons or screens
Evidence to submit: Table of roles and what each can create, read, update and delete

Requirements: Data flow diagram
Minimum: Every external entity, process, data store and trust boundary
Evidence to submit: Level-1 DFD

Requirements: Threat analysis 
Minimum: STRIDE applied to every flow that crosses a trust boundary 
Evidence to submit:: Threat table with a mitigation for each threat

Requirements: Data protection 
Minimum: Lawful basis, data minimisation, retention period, and who can see personal data
Evidence to submit: Short GDPR write-up
